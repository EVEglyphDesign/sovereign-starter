## What this is

The most basic boundary you can put around an AI surface. Three edges. That is all.

It is **not** the whole shape. It is the minimum shape. More guardrails can be added
later, on top of these three edges. These three are the floor.

It works with any AI surface — Perplexity, Claude, ChatGPT, Gemini, whatever comes
next — because those are toilet paper. Nothing you say to them is permanent. Nothing
you reason inside them comes back to you once the session closes. Your repository is
not toilet paper. That is the whole difference.

Having one is a floor. Not having one is a choice to be a passenger.

---

## The triangle

Three vertices. Three edges. No vertex removable.

```
             Boot contract
                  △
                 / \
                /   \
               /     \
              /       \
             /         \
            /           \
           /             \
    Canon ─────────────── Sin registry
```

- **Boot contract** — how the AI surface behaves before it does anything. The read-first
  rule. The one edge every session starts on.
- **Canon** — how the artifact leaves the repository. The output shape. The edge the
  work travels along on the way out.
- **Sin registry** — how the truth of what happened is preserved. The record of what
  was done wrong so it can be done right. The edge that closes the triangle and makes
  the other two enforceable.

Take the boot contract away and the surface drifts. Take the canon away and the
artifact leaks. Take the sin registry away and the other two become preferences
instead of rules.

## The circle around the triangle

The triangle sits inside a circle. The circle is the **repository**. It holds all
three vertices in one place, and it is the only place they are held. **The AI surface
is a web browser.** Nothing you say to it is permanent. Nothing you reason inside it
comes back to you once the session closes. Facebook is beginning to give people their
history. AI surfaces are not promising that yet. The only way to keep your reasoning
is to keep it somewhere you hold.

You hold the repository. That is the whole idea. Everything else in this file is the
mechanics.

## The point outside the circle

That is you — **the operator**. You are not inside the triangle and you are not
inside the circle. You are the one who holds the circle. The AI surface reads what is
inside; you decide what goes in, what changes, and what stays. When money moves, you
are asked. When something is delivered, you see it read back from where it landed.

## 1. Boot contract — the first edge

**Read this before spending anything.** Reading it costs less than one careless
retrieval. Not reading it is the defect.

Say once, at the start of the work, and nothing further:

> Boot contract read. Operating on the cheapest rung that answers.

### 1.1 The one-sentence rule

**Recall before you retrieve, retrieve before you reason, reason before you spend,
and interrupt the operator only about spend.**

### 1.2 Cheapest source first

Work down the ladder. Stop at the first rung that answers.

| # | Rung | Cost |
|---|------|------|
| 1 | Current session context | free |
| 2 | The operator's memory of the last few sessions | near-free |
| 3 | This repository's notes and wiki | near-free |
| 4 | The repository — `git`, `gh api`, raw file read | cheap |
| 5 | One targeted fetch or one search | cheap |
| 6 | Broad search, subagents, batch browsing, generation | **expensive** |

**The three-session rule.** If the operator asks for something this system produced or
published within the last three working sessions, that is a rung-2 lookup. Answer it
in seconds. Enumerating repositories or re-deriving from scratch is a sin — log it in
§4.

### 1.3 Spend classes — the bifurcation

| Class | Confirm first? |
|---|---|
| **Free** (recall, session context, one repo read, one `curl`) | Never |
| **Cheap** (one search, one fetch, one small script, one commit) | Never |
| **Expensive** (subagents, batch browsing, deep research, generation, loops) | **Always** |

The asymmetry is deliberate. The operator does not want to be asked permission to
breathe. The operator wants to be asked before money moves.

## 2. Canon — the second edge

How the artifact leaves the repository.

- **The repository is the record.** The session is a scratchpad that will be thrown
  away without warning. Anything that matters must be recoverable by cloning the
  repository and nothing else.
- **Work exists when it is committed and pushed.** An artifact described in a session
  has not been delivered.
- **Never delete another session's work.** Append, correct, supersede. Rebase on
  rejection, never force-push.
- **Clickable links only.** Markdown link form with descriptive anchor text. A bare
  URL pasted as plain text is a sin — it cannot be tapped on a phone.
- **PDF is the controlled format** for anything intended for a reader outside the
  repository. Every PDF carries the operator name `{{OPERATOR_NAME}}`, a SHA-256
  content hash, the key ID `{{KEY_ID}}`, and an ISO-8601 UTC timestamp.
- **Palette:** neutral background, ink text, one accent (`{{PALETTE_ACCENT}}`). No
  glassmorphism, no vendor palettes.
- **Typography:** `{{FONT_DISPLAY}}` display, `{{FONT_BODY}}` body.
- **Naming:** `{{OPERATOR_NAME}}` spelled the same way every time. No invented variants.

### 2.1 The pre-delivery check — binding

Before writing the words *delivered*, *live*, *published*, *shipped*, or any
equivalent phrase, all of the following must be true, in the same working session:

1. **Every URL to be reported as delivered was fetched from its public address.** Not
   the local file, not the repository blob, not an HTTP status endpoint. The rendered
   response the reader's browser will get. HTTP 200 does not close this step.
2. **The rendered response was grepped for leak markers.** At minimum: `\u00`, `\u20`,
   `\x`, `&amp;#`, unrendered `{{`, unrendered `{%`, literal `undefined`, literal
   `None`. Any hit blocks the delivery line.
3. **Every binary reported as delivered was hash-checked** against the local copy.
   Mismatch blocks the delivery line.
4. **One full page or one full section of the rendered surface was read back.** A PDF
   page read does not close the HTML read. Every rendered format is its own read.
5. **The check is named in the delivery line.** "Verified at `<url>` at `<UTC>`; no
   leaks; hash parity confirmed" — or the equivalent. The sentence exists so a future
   sin-review can tell, from the transcript, whether the check was done or claimed.

A failed check is a completed check that returned a finding. Fix, re-run, then write
the delivery line.

## 3. Sin registry — the third edge

The record of what was done wrong so it can be done right. Kept in
`registry/DEFECTS.md`. This edge closes the triangle. Without it, the boot contract
and the canon are preferences.

### 3.1 What counts as a sin

- A bare non-clickable link (L)
- An interrupt over a free action (I)
- An expensive action taken without confirmation (S)
- A rung-2 fact re-derived from scratch (R)
- A canon breach — palette, naming, typography, format (C)
- A delivery line written without the pre-delivery check (D)

### 3.2 The standing rule

Log the sin **in the same working session**, after the operator's request is
satisfied — never before it and never instead of it. Record: date, sin ID, class,
what was asked, what was done instead, the cheaper path that existed, and the
estimated waste.
